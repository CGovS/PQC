How you actually migrate to post-quantum crypto

The algorithms are the easy part — NIST finished them (FIPS 203/204/205) and they're open source. The real work is the four steps below. This repo is a working model of the one enterprises keep skipping: step 2.

1

Discover

Inventory every place RSA/ECC is used — TLS, code signing, VPNs, tokens, stored data. The unglamorous 80%.

in the maze · all crypto flows through one seam, so discovery is trivial by design
2

Add agility

Put crypto behind an interface + registry so the algorithm is a config value, not a hardcoded call. This is the missing piece.

in the repo · LockBox interface + registry — the actual deliverable
3

Hybrid rollout

Run classical + PQC together (e.g. X25519 + ML-KEM) so you're safe if either breaks. Defeats "harvest now, decrypt later."

in the repo · the registry can serve either — or both — by name
4

Cutover

Flip the default to PQC, keep classical as fallback, and monitor. No rewrite — just a new default.

in the demo · the before → after flip is this cutover
Applying a KEM to real data (KEM-DEM). ML-KEM only transports a shared secret — it isn't a general encryptor. So you wrap it, exactly how PQC ships in practice:
ML-KEM.encapsulate → shared secret → KDF → AEAD encrypt your payload
The public-key step is now lattice-based, so Shor has nothing to factor. In this repo that's cryptolayer/pqc.py.

Reality check — why the live break is a toy, and why it still proves the point

A statevector simulator holds 2^(qubits) amplitudes. The maze moduli are simulable; real RSA is not — by a wide margin. The scaling argument, not the tiny break, is what generalizes.
